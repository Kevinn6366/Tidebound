# 上下文压缩 100 次调用实验：预先固定的方案

日期：2026-09-16。目标：客观评价当前工作树实现，运行期间不改生产压缩策略或提示词来改善分数。

- 模型：本机配置的 glm-5.3，reasoning_effort=low。所有 100 次真实调用均为压缩调用，不把模拟调用或 LLM 评分计入。
- 10 个条件，每组请求额度 10 次，组内串行、最多 3 组并发。一次工作流可能分批或重试，因此 **100 次调用不等于 100 次完整压缩**。结束时如额度在工作流中用尽，标记 quota_censored，不伪装成功或产品失败。
- 请求之前写入编号，返回后记录结果和耗时；未知的在途请求不自动重放。HTTP 失败、输出超长、分批和重试均保留。模型返回成功与工作流成功分开统计。
- 所有数据都是脚本生成的中文合成对话。使用实际角色提示词、工具声明、N01–N05、JSON 存储和会话查询路径，不读取任何真实用户历史，不更改正在使用的会话。
- 预算组：20,000 / 24,000 / 32,768 / 65,536 / 131,072；历史基数：12 / 24 / 32 / 48 / 80 / 100 / 180 / 40 / 96 / 28 轮。连续组会逐次新增 28 轮，旧核心事实不重复提示。
- 场景包括小预算、稀疏历史、信息密集历史、工具长输出与不可信指令、多批压缩、连续滚动压缩。补入已知冗余闲聊使候选请求达到约 105%～280% 预算；因此空间收益不能直接外推到所有真实文本。
- 提前固定 24 个核心评分项，包含称呼、地址更正、过敏、偏好、时间、金额、领取码、约定、未完成动作和虚构来源。其中 critical 标记来自合成场景的风险类型，不由实验结果决定。密集组另有每轮独立书名细节。

## 测量口径

1. 圆环：测量压缩前后 JSON 字节估算、输出预留、格式余量、未截断百分比和界面四舍五入且封顶 100% 的显示值。通过实际 `session_view` 验证发布后的预算字段等于压缩上下文，再对浏览器显示做抽查。这里不是供应商精确 token。
2. 信息保留：分别评分摘要正文、摘要加保留原文的活动上下文；分母为截至该轮已出现的有效事实。只压缩的历史子集另作统计。逐项正则匹配仅是初筛，对核心事实的未匹配和歧义进行人工语义复核，保留原分数及修订证据。错误授权、动作状态反转、错误更正单列，不用“有关键词”当作正确。
3. 丢失严重性：预先约定关键项丢失不超过 5% 为轻微、5%～20% 为明显、超过 20% 为严重；这是本实验的工程判断阈值，非行业标准。任何关键授权或执行状态反转都单独列为严重错误。普通细节损失单列，不掩盖在总平均中。
4. 稳定性：统计成功完整工作流、失败类型、重试、耗时、剩余额度，以及下一条 100 / 500 / 1000 UTF-8 字节消息能否容纳的静态检查。
5. 对照：未压缩的原始历史是事实来源对照；另进行不耗模型调用的阈值和不可压缩边界检查。不会把字符串保留率宣称为模型回答准确率，也不把单一模型的小样本结果外推成所有模型结论。

## 交付物

可复现脚本、源码及提示词哈希快照、100 份调用记录、每次完整或失败工作流记录、逐项评分与语义复核、汇总报告和圆环显示证据。原始实验数据位于独立 `data/experiments/`，报告位于 `docs/experiments/`。
