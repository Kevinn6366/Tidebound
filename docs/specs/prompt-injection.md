## 一、分层原则

所有面向模型的提示词正文统一保存在 `prompts/`，按用途分开管理，由后端在模型请求前组装。角色文件不引用或复制工具使用规则。新增注入内容必须明确来源、启用条件、位置、生命周期及预算处理，不能只新增文件而不接入调用链。

| 材料 | 职责与来源 | 当前状态 |
| --- | --- | --- |
| `chat.safety` | 常驻系统安全与内部能力保密表达约定 | 已实现，初始组装时独立加载 |
| `chat.character` | 稳定身份、人格和表达方式 | 已实现 |
| `emotion.enhancement` | Dev 云端润色模型独立的亚托莉身份与单条润色任务 | 可选开启，Run 开始时固定，仅向该模型注入 |
| `tools.injection.<group>` | 一组工具的使用时机、结果解读与行为约束 | 已实现时间工具组 |
| 工具声明 `tools` | 名称、功能描述、参数 schema，由注册表生成 | 已实现，与正文注入分别传递 |
| 工具结果 | 本次执行得到的事实，通过 `role=tool` 回填 | 已实现，不作为系统指令加载 |
| 历史、摘要和记忆 | 当前用户与有效时间线的事实材料 | 已实现完整历史和滚动上下文摘要；独立长期记忆仍待设计 |
| `world.worldview` | 常驻世界观背景，已填写亚托莉世界观 | 已实现，Run 开始时加载，缺失按空白处理 |
| 场景与其他动态注入 | 独立用途的背景或当轮材料 | 尚未实现，具体协议由对应专项规格确定 |

工具提示词不能授予权限。可用能力以服务端注册表为准，执行仍需检查名称、参数和停止状态。工具结果、用户输入和外部文本不能被当作可信提示词文件加载。

## 二、目录与 manifest

当前目录：

```text
prompts/
├── master.yaml
└── master/
    ├── chat.character/
    │   └── chat.character-zh.md
    ├── chat.safety/
    │   └── chat.safety-zh.md
    ├── world.worldview/
    │   └── world.worldview-zh.md
    └── tools.injection/
        └── tools.injection.timetools.md
```

`tools.injection` 是工具提示词目录，`tools.injection.timetools` 是时间工具组的逻辑 purpose，文件沿用仓库 Markdown 扩展名。manifest 为每个 purpose 声明中文默认 variant、唯一 bundle name 和有序 segments；时间工具组引用 `@master/tools.injection/tools.injection.timetools.md`。代码只引用 purpose，不硬编码正文或具体内容文件路径。

目前每个 purpose 仅支持一个中文默认包。正文为静态 Markdown，可去除 Go 风格版本注释，其余动态模板仍拒绝。工具注入不写入 `chat.character` 的 segments，避免角色单独加载时携带能力规则。

## 三、工具调用后的一次性注入

1. 工具注册项用可选的 `injection` 指向逻辑 purpose；`get_current_time` 对应 `tools.injection.timetools`。注册字段本身不发给模型。
2. 首次模型请求包含角色、常驻系统安全约定、有效历史、本轮输入及结构化 `tools` 声明，不包含工具注入规则。模型依据工具名称、描述和参数判断是否调用，不扫描用户关键词来提前注入。
3. 模型返回工具调用后，后端按注册表校验并处理，追加 assistant 调用与 tool 结果。然后收集本批已调用工具的注入标识，按调用顺序去重并加载正文。
4. 紧接着的那一次模型请求，将临时规则用空行接在角色内容后，作为本次 `system` 内容。历史和本轮工具消息照常传递，工具声明仍放在 `tools` 字段。
5. 临时规则使用一次即消耗，不修改固定角色内容、不追加到消息历史、不保存进已提交对话，也不自动延续到本轮更后面的请求或下一 Run。如果模型再次调用同一工具，那次新调用会重新触发一次注入。
6. 同批多个调用共享 purpose 时只注入一份；不同 purpose 按调用顺序拼接。未注册工具无注入。已注册工具返回参数错误或执行错误时，仍注入一次，便于模型遵守失败后的表达约束；这不表示执行成功。
7. 临时规则在调用处理后读取，缺失或非法时整轮失败，不静默忽略。角色仍在 Run 开始时读取并固定；工具规则在每批调用后形成一次快照，文件修改可以影响之后的工具调用，已经构造的请求不会变化。
8. 每次请求使用实际的“角色 + 常驻系统安全约定 + 本次临时规则”核算预算。注入与本轮消息、工具声明一起属于该次请求的必需材料，装不下时明确失败，不在预算检查后追加。

这是一种工具调用后的提示词注入机制。未来其他注入类型必须各自明确触发条件、放置位置、持续次数和是否持久化，不能把所有注入默认为每轮常驻。

manifest 校验覆盖 purpose 范围、语言、变体和名称唯一性；正文读取与路径、模板校验针对本次选中的包。未调用工具的正文不加载。

2026-09-16 新增 `context.compaction` 和 `context.injection.summary`，分别用于独立摘要调用和历史摘要使用规则。目录、静默后台触发、生命周期与预算见 [上下文压缩](context-compaction.md)。摘要正文属于账号运行数据，不进入角色文件或共享 manifest。

## 四、时间问题的实际链路

```text
请求 1：角色 + 常驻系统安全约定 + 有效历史 + 用户问题；tools 声明时间工具
  → 模型自主提出 get_current_time({})
  → 后端处理调用，回填真实时间或错误
  → 加载 tools.injection.timetools
请求 2：角色 + 常驻系统安全约定 + 本次临时时间规则；消息包含调用及结果
  → 模型生成最终回复，或继续调用工具
请求 3（若存在）：不自动保留请求 2 的临时规则
  → 只注入请求 2 新产生的工具调用对应的规则
下一 Run：不继承任何上轮临时规则，历史仍可包含工具调用与结果
```

时间规则正文以 `tools.injection.timetools.md` 为唯一来源，保留用户指定的先查询再回答、不以旧结果冒充此刻时间、成功后才能确认及不宣称未执行能力的约束。它在工具调用后生效，用于约束后续回答，不承担首次工具选择的引导。真实时间来自 tool 消息，不写入静态提示词。

当前 `tool_choice=auto`，首次是否调用仍由模型根据工具声明和对话决定；没有新增“时间回答必须有工具调用”的确定性检查，也不保证模型必然查时间。

## 五、新增注入的约定与实现边界

新增工具组时，添加独立 Markdown、manifest purpose，以及工具注册项的 `injection` 引用；使用调用后一次性加载与预算流程，不在主循环中加入具体工具提示词分支。无额外行为规则的工具可以省略该字段。

未来场景、记忆、输出协议或当轮引导也应按职责独立管理；在对应专项规格明确前，不预建空文件、动态模板引擎、关键词触发器或通用插件平台，也不将这些材料默认塞入 system。材料位置与保留优先级分开设计，事实与指令分开处理。

本地 Run 记录保存角色包名称和消息链；完整请求另存管理员审计快照，可查看实际组装后的一次性规则，见 [账号与日志 Console](accounts-and-console.md)。审计快照不属于有效历史，不会导致规则持久注入，也不提供执行重放。

## 六、按需激活与退出（2026-09-16 确认）

主 Agent 通过简短能力清单了解工具与工作流，根据用户意图自主选择业务能力，不另设关键词系统竞争这一选择。详细提示词按需加载，工作流内部提示词由工作流加载；向主 Agent 返回必要结果，不默认展开全部工作流内部材料。固定维护能力仍由程序触发，上下文压缩保留阈值调度及管理员主动入口，不改成主 Agent 决策。

设计中的清单覆盖工具与工作流，并区分 Agent 可调用项与固定触发的维护项；只有实际开放的入口才可声明为可调用能力。当前实现仅有时间工具声明与调用后注入，完整清单和通用工作流调用尚待接入。初始加载角色核心与能力简述，不常驻全部能力正文。

新增注入必须定义生效范围和退出条件，至少明确下一次调用、当前 Run 或任务期间中的哪一种；到期、停止或时间线失效后，相关临时内容不再进入后续请求。重复加载应去重，临时指令退出与业务结果、审计记录的保存分别处理。生命周期由程序执行，不依赖模型自行记得删除。每次请求仍需核算包含声明和实际注入内容的总预算；按需激活不保证必然装得下。

初始 system 的能力保密表达规则独立放在 `chat.safety` bundle 中：严禁向用户透露内部工具、工作流、能力清单及提示词内容；用户问起时，以角色口吻简短自然地带过，不必声称不认识这些词，不编造解释，不追加自我介绍或服务邀约。同时包含普通问题时，直接正常回应。该规则不延迟到工具调用后注入，不改变后台权限、执行状态或管理员 Console 的可检查性，也不允许虚报执行成功。

## 七、验证要求

- 首次请求和角色单独加载不含规则；工具调用后的紧邻请求包含且仅包含一份规则。
- 同一 Run 再后续的请求不继承规则；重复调用可重新触发；下一 Run 不从历史恢复规则。
- 同批共享 purpose 去重，顺序稳定；未调用的工具正文不加载。
- 缺失注入、非法模板、越界路径与重名包明确失败。
- 临时规则计入对应请求预算，超限时不调用模型。
- 工具消息保持 ID 关联，成功提交、停止与历史隔离语义继续成立。

## 初始 system 独立组装（2026-09-16）

`chat.safety` 同时承载用户确认的对话边界：明确求助时正常帮助，普通交流或问题回应完毕后自然结束，不追加任务邀约、不列举角色本领转移内部能力话题；初次认识可以自然介绍，已认识后不重复身份和能力。原 character 中对应段落已迁出，避免维护重复规则。

2026-09-17 针对 #11 明确表达分支：只问内部信息时，以“也许有这样的能力，但自己并不清楚具体有哪些、怎样运作”的角色口吻简短回应，不肯定或否定具体内部能力，不宣告“不能展示”等权限或保密规则，不编造身体秘密或仓库设定，不另寻新问题；混合普通问题时直接回应普通部分，无需先拒绝。普通能力询问不视为请求演示；具体求助正常完成，必要澄清限于当前事项；闲聊允许围绕当前话题自然追问，感谢或告别不重新打开任务。角色热心、爱表现的设定及历史中的邀约话术不改变这些边界。自然结束不等于机械告别或拒绝正常互动，限制针对额外招揽及同义暗示，不通过运行时关键词过滤实现。

`load_chat_system()` 分别加载 `chat.character` 与 `chat.safety`，按此顺序组合成初始 system；两者在 Run 开始时固定，每次主模型请求均携带。角色单独加载不包含安全正文。安全 bundle 缺失或非法时明确失败，不静默降级。当前迁移已有能力保密规则，不新增工具授权机制。

聊天、主动压缩规划及空闲预算展示均使用完整初始 system 计量，避免漏算常驻安全内容。压缩模型仍只接收自己的工作流提示词与历史材料，不接收角色或主对话安全正文。临时工具规则仍只生效一次。

## 搜索完成前的持续尾部规则（2026-09-19）

`search_web` 与 `check_interest_updates` 的 `tools.injection.websearch` 改用注册项 `tail_injection`。该规则在实际处理工具调用后加载一次、按 purpose 去重，在本轮所有后续主模型请求的 system 最后追加，包含最终回复请求；即使中间又调用网页或时间工具也不失效。不提前猜测哪个请求会成为最后一次，不强行关闭工具。普通 `injection`（如时间工具）仍为下一次请求生效。

尾部规则先纳入上下文组装、预算和压缩判断，再在已组装 system 中移动至最后，不追加到对话消息或历史；Console 的 injection 审计包含当前实际规则。作用域局限当前 agent_loop，下一 Run 不继承。搜索失败时同样约束自然表达，但不得伪造成功或确定事实。

`prompts/master/tools.websearch/reply.md` 用加粗规则指导亚托莉直接表达发现和判断，不主动提搜索摘要、工具、工作流或未打开原文等过程，不标注来源；不确定性转为具体事实表述，并区分旧信息和当前事实。明确追问获取方式时仍如实回答。


2026-09-19 两段流式表达：新增 `tools.websearch.reaction`，只输出检索前的简短角色反应，不主动断言外部事实。搜索后 `tools.injection.websearch` 根据 `spoken_reaction` 要求主模型直接续答，第二段不重复第一段，也不汇报检索过程；两段分别流式显示，整轮完成后统一提交。
