# 长期滚动摘要

2026-09-22。单 worker dev 实现；独立于上下文压缩，后台静默生成，主模型只获得读取能力。长期摘要为未来知识图谱保留来源依据，本期没有实现知识图谱、向量检索或主动通知。

## 职责与材料

上下文压缩继续使用 `context.compaction`，遵守原有预算阈值和近期原文保留规则。长期摘要使用独立 `memory.rolling_summary` 提示词，整理共同经历、关系变化、持续话题、重要约定及明确偏好和边界。它不自动注入每轮主请求，也不改变已保存的事实或跟进状态。

摘要正文采用包含自然语言条目的 JSON，每项包含类别、正文、来源 Run ID、事实来源类型和可空的事件时间。来源类型区分用户明确表达、角色表达和推测；讲述时间来自原始轮次，不能冒充事件发生时间。提示词要求保存更正及变化，不把角色承诺当成已执行业务。

生成输入仅包括旧长期摘要和新增已提交轮次的用户正文、最终角色回复、轮次 ID、种类及时间，不读取工具链、思考、失败轮次或管理员审计。登录问候作为已提交角色表达参与整理，不被当作用户事实。长历史按完整轮次分批，最多16批；单轮超限、输出未正常结束、JSON非法、来源越界或输出超长均保留旧版。所有批次成功后才发布完整版本。真实模型验收发现偶发非法JSON后，增加一次结构失败重试：在同一总超时内最多两次完整生成尝试（每次最多16批），仍失败则保留旧版，不修补或接受非法JSON。引用存在及格式校验不能证明概括语义忠实，未来知识图谱的重要事实仍须回查原文。

## 调度与读取

成功提交后调度后台维护；会话开始时也检查已有历史，以恢复重启前未完成的整理。没有新增有效对话则不调用模型。每账号最多一个任务，默认延迟2秒合并近期提交；生成期间新增的轮次会在后续循环追赶。不新增持久化队列或每用户常驻定时任务；后台失败记录安全日志，后续会话事件再尝试。重启后未发生会话事件的账号不会主动扫描补算。

后台任务不占主 Run 状态，不输出聊天消息或预览，不要求主回复等它。模型审计用途为 `memory.rolling_summary`，Console 显示“长期滚动摘要”。普通停止只影响当前主执行，不取消基于旧已提交历史的维护。

`read_conversation_summary()` 通过现有 `use_tool` 目录开放，无业务参数、无需联网权限。账号、时间线和历史范围由 runtime 绑定。工具读取最新且适用于当前 Run 历史快照的版本，返回摘要、版本、生成时间、覆盖到的轮次及时间、尚未覆盖的轮数。尚无版本返回 `not_generated`，旧时间线返回 `invalidated`；读取不会触发或等待生成。

跟进的创建、更新和取消工作流从同一个 `ConversationMemory` 入口读取摘要，并附带尚未覆盖的近期原文。当前请求和原事项照常传入，用户逐字证据仍须通过原有校验。摘要仅补充理解，不能变成状态、指令或授权。跟进输入整体纳入预算；材料过大时明确失败，不静默丢弃原文或偷偷生成新的摘要。主模型可以通过独立读取工具回忆背景，并通过原有历史回看工具核实细节。

## 存储与一致性

版本保存到 `data/agent/<owner>/rolling_summaries/<timeline>/<summary_id>.json`，与压缩摘要分开。保存版本链、生成时间、覆盖 Run ID 前缀、覆盖时间、逐项来源、提示词哈希和模型名称。

读取仅接受当前历史的完整前缀，旧 Run 不能读取后续轮次的摘要。提交前重新校验任务取消、当前时间线、有效历史前缀和已发布覆盖进度；检查与原子写入之间无 await。不会用落后的结果覆盖更新版本。不同账号以服务端绑定路径隔离。

清空先切换时间线，撤销主执行并取消、等待后台维护，然后删除长期摘要及原有可回忆历史。供应商取消后迟到的结果不能发布。服务关闭取消并回收任务。当前没有新增管理员任意轮次回退入口；前缀校验支持拒绝超出恢复历史的摘要，但不宣称已实现完整回退功能。文件原子发布适用于单 worker，不支持多进程并发写入。

## 配置

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `TIDEBOUND_ROLLING_SUMMARY_MODEL` | 基础 `TIDEBOUND_LLM_MODEL` | 独立后台模型名称；使用基础 LLM 地址和凭据，不继承 Console 临时主渠道 |
| `TIDEBOUND_ROLLING_SUMMARY_CONTEXT_LIMIT` | 65536 | 独立上下文预算，沿用 JSON UTF-8 字节估算 |
| `TIDEBOUND_ROLLING_SUMMARY_MAX_OUTPUT_TOKENS` | 4096 | 供应商输出上限及本地输出预留 |
| `TIDEBOUND_ROLLING_SUMMARY_MAX_BYTES` | 20000 | 摘要 JSON 字节硬上限，最多50项 |
| `TIDEBOUND_ROLLING_SUMMARY_DELAY_SECONDS` | 2 | 后台合并延迟，允许0至60秒 |

超时沿用基础运行超时。后台模型无工具权限、角色提示词或情感增强包装。运行数据及凭据不进入版本控制。

## 2026-09-22 来源与变化保留修订

真实 Chrome 多轮验收发现旧稿中的角色说法会被继续标记为用户事实，且更新时有时只剩最新状态。生成现在在容纳新增完整轮次后，使用剩余预算回查旧条目 source_run_ids 对应原文，优先近期来源，保留 user/assistant 边界。无法容纳的旧原文不会强行塞入预算，也不声称已回查；不访问其他账号、时间线、推理或工具链。

条目新增 evidence：来源 run_id、speaker（user/assistant）和连续逐字 quote。旧存储兼容空 evidence；新生成的 user_statement/assistant_statement 必须有对应说话者的非空引句，且引句必须在本次提供的原文中，或原样继承旧版已有引句。引句来源必须属于该条 source_run_ids。缺失、伪造、角色错配导致整个候选失败，保留旧版；重试附带至多500字符的校验反馈，仍只有一次重试。没有原文和历史引句的旧条目只能保留为明确未核实的 inference。已有旧版不会仅因升级自动变成已核验版本，需等待成功更新。

提示词要求按说话者拆分、保留最初计划—更正—当前状态及虚构限定，优先删除重复技术细节和自评，避免无关话题挤掉发展过程。引句校验只能证明来源和说话者匹配，不能自动证明概括受引句完整支持，也不核验外部事实。话题发展保留仍需要真实多轮质量验收，不能宣称语义无损。

独立复核：每批先生成候选并校验引句，再以候选条目及其引句作为独立请求，复核正文是否混入其他说话者的主张或缺证据的推断。复核结果再次通过引句、来源、大小与正常结束校验才进入下一批。两次请求均使用 memory.rolling_summary 审计用途，step 区分调用；没有可见预览，也不等待主回复。每次尝试最多16批、每批2次模型请求；失败最多重试完整流程一次，仍受原总超时约束。独立模型复核改善概括忠实性，但不是数学证明或外部事实验证。

## 2026-09-22 稳定证据引用修订

针对真实供应商反复改写引句、抄错UUID的问题，模型输出改为 `evidence_refs` 短编号，不再输出引句、说话者或来源Run ID。服务端为每批建立确定的编号表，生成与独立复核共用同一张表；编号仅在该批请求范围有效，不作为持久化全局ID。旧已验证引句直接入表，新增/回查原文按最多100字符连续分块，保留Markdown及所有原字符。旧条目缺少引句时以unknown证据兼容，只能作为inference，不能升级为确定用户事实。

模型只编写概括并选择编号；代码从当前表还原原始Run ID、说话者和引句。未知编号、归属与说话者不符、恢复后超过字节限制均拒绝发布。存储和读取工具仍返回原有完整证据格式，客户端不用理解短编号。恢复后照常进行逐字校验、预算、取消及时间线发布检查。两阶段模型调用继续负责发展链与概括忠实性的质量控制，引用机制并不证明概括语义或外部事实。

稳定引用实测中，含完整证据的摘要约14KB，超出旧纯摘要12KB预算。后台默认输入预算调为65536、完整持久化摘要上限调为20000字节；模型输出仍默认4096 tokens，支持环境变量覆盖。未知引用始终立即拒绝；生成草稿中的归属错误允许交给独立复核纠正，最终发布前仍严格校验说话者。

最终交付验收：Python全量285通过，Chrome专项2通过；开发管理员真实供应商连续发布覆盖23、24、25轮的三个版本，全部引句再次对照原文校验。Chrome读取覆盖24轮的最新版时uncovered_turn_count=0，随后读取轮次也已纳入25轮摘要。第三版经一次归属校验失败重试后成功。详见[稳定引用交付验收](../experiments/2026-09-22-stable-summary-delivery.md)。

## 2026-09-22 简短用户状态摘要修订

依据最新用户确认，生成与独立复核提示词改为优先保存称呼、明确位置、近况、偏好、有效计划和互动边界，通常3～8条、每条10～40字，不凑条数。当前摘要只保留最新有效状态，旧版本保留演变历史；仅在理解当前状态必要时简述变化原因。本节取代此前要求当前正文始终保留完整发展链的提示词要求。

普通寒暄、角色自我介绍、安慰比喻、重复回应和无持续价值的假设闲聊一般省略。临时近况保留时间范围或“上次提到”，不能永远冒充当前状态；计划地点不能写成当前位置。用户条目中混入角色说法时删除混入内容，不用解释归属的附注掩盖混合证据。重要经历和关系变化仍可简短保留。

本次仅调整摘要提示词及规格，不改变证据协议、读取工具、事实存储或跟进状态。2500字节为模型输出目标，不是新硬限制；证据仍保存在后台并由现有读取工具返回。已有摘要在后续成功维护时更新，提示词调整不会立即重写历史版本，也不会自动修复独立facts中的旧计划。
