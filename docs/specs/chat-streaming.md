# 聊天流式输出

日期：2026-09-14。用户要求回复随 LLM 生成逐字显示，覆盖首版仅在整轮完成后展示正文的交互。关联 [Agent loop v0.01](agent-loop-v0.01.md)。

## 数据流

1. 前端提交用户正文，服务端返回 Run ID，后台执行生命周期保持独立。
2. 聊天 Run 为模型适配器绑定专属正文回调，模型请求使用 `stream=true`，不受 `TIDEBOUND_DEBUG` 控制。
3. SSE 解析器收到供应商 `content` 分片后更新 Run 内存中的累计正文预览。思考字段不混入页面回复，工具参数继续按完整调用协议组装。
4. 浏览器订阅 `GET /api/chat/runs/{run_id}/events`。接口校验登录账号与 Run 归属，返回 SSE `data` 事件，每个事件是完整 RunView，包含 `preview`、本轮输入、状态及最终回复。最多约每 30ms 合并推送一次变化，不重复推送相同快照。
5. 前端替换累计预览，再按字符逐步显示已经收到的正文；不会等整个模型响应结束才开始打字。生成结束后继续显示尚未呈现的字符。历史消息直接显示。

工具调用前后的模型请求各自重置预览。发现工具调用后清除该模型请求的中间正文，下一次请求展示新的正文；不能将工具前的过渡文字当成最终回复提交。

## 完成、停止与恢复

- `preview` 只存在内存，排除在 Run JSON 序列化之外，不进入有效对话历史或 UI 存档数据。页面上临时显示不等于正式提交。
- 只有完整解析模型结束协议、通过循环与停止检查后，才沿原路径提交用户输入、工具链和最终回复。
- 停止、异常、截断或超时均清空预览。迟到分片不能恢复已经停止的 Run；页面恢复上次已提交内容。
- 流式订阅断线或页面关闭只取消订阅，不调用停止。浏览器重连时收到当前累计正文，以替换方式展示，不重复追加文字，也不重发用户输入。
- 页面刷新通过会话查询找到活动 Run，再订阅它；终态后 SSE 关闭。状态查询仍作为页面恢复与发送结果确认的入口。
- SSE 只提供当前用户可见的正文、状态和工具记录，不包含 system 提示词或思考内容。完整模型上下文仍仅通过管理员 Console 查看。

## 验证

使用受控供应商分片验证：debug 关闭时仍为流式；模型尚未完成时正文已经可见；逐字增长；页面刷新接回同一 Run；停止撤掉临时文本且无有效历史；工具结果回填与 Console 原始请求快照保持正确。此验证不代表真实供应商的生成速度或分片粒度。

## 上下文预算展示

底部快捷栏移除“工作”和“备忘”按钮，在对应位置显示预算圆环，支持点击展开明细。用量由后端在每次模型请求完成上下文选取后计算，口径与预算检查共用，包含一次性规则、工具声明和实际选择的历史；不按前端聊天条数估算。

圆环比例为 `(输入估算 + 回复预留 + 格式余量) / 总预算`，显示的是预算占用而非精确计费 token；接近上限时变为黄色、红色。详情列出总预算、输入估算、回复预留、格式余量与剩余额度。用量属于最近一次模型请求，不实时估算尚未发送的草稿，也不把流式输出重复加到已预留额度上。

统计随 RunView/SSE 更新，并保存到 Run 记录，完成后刷新仍可查看。无统计的旧记录或从未发起请求的账号显示未知，不伪造 0%；仍可查看当前预算配置。停止/失败后会话查询恢复最近已完成轮次的统计。历史文件不因展示功能重新调用模型。

## 2026-09-16 对话试验边界

工具调用前的过渡正文可以暂时展示并撤回，不进入历史剧情 Log 正文。页面 Log 读取已提交会话消息，工具记录仅展示调用名称、参数、结果和状态；执行记录与管理员审计保留原始调用链。

后续试验：允许多条用户消息归入同一个 Run，不建立逐条消息对应多个 Run 的连续发送队列。本次仅记录方向，当前执行中拒绝新发送的行为保持不变。实施前需明确输入接收截止点、模型请求期间的补充如何进入后续调用、完成竞争、停止及刷新恢复，并实测交流效果。

## 2026-09-17 登录问候与时间

欢迎执行 `kind=meet` 在后台完整生成并提交单条 assistant 消息，不伪造用户输入；页面进入时未完成则等待同一 Run，已完成则逐字展示已有结果。普通查询不触发问候。RunView 增加 kind、created_at、completed_at，SessionView 增加 meet_run 与 timezone；历史消息包含 kind、created_at 和 time_estimated。正式消息时间进入 Log，欢迎生成失败可显式重试或直接聊天。完整语义见 [登录问候与对话时间](welcome-meet.md)。

## 2026-09-17 展示时间修正

角色消息的 Log 时间以首次逐字展示为准，通过页面正文出现后的幂等确认记录 `display_started_at`，后台完成时间继续单独保存。标题页后台订阅不确认展示；工具预览清空会递增 `display_revision` 并撤销该段展示时间，拒绝旧版本迟到确认。新消息未展示时历史时间为空，旧消息回退时间标记为估算。时间元数据不再作为 `message_time` 前缀注入模型消息正文，详见 [登录问候与对话时间](welcome-meet.md)。
