## 一、目标与范围

将以下两项作为一个未来 GitHub issue 跟踪：

1. 参考 SillyTavern 的预算与材料分项方式，先确定每次模型调用的输入预算，再选择和组织上下文材料。
2. 将世界书相关需求简化为一段专门介绍有哪些场景、场景背景是什么的提示词，通过 prompt bundle 加载并注入上下文。

本次交付为规格与 issue，不实现 runtime、模型调用、场景提示词正文或管理界面。上下文控制仍属于宏观规格的主线职责，未来 issue 表示尚未排入实施，不意味着实现模型调用时可以绕过预算与有效性检查。

## 二、上下文预算与材料选取

预算以一次模型调用为单位。同一 Run 在工具调用前后多次请求模型时，每次都需要重新核算。参考关系为：

```text
请求输入预算 = 本次配置的有效上下文上限 - 输出预留 - 必要余量
```

有效上限必须适配实际模型能力；工具定义、消息格式及其他请求开销应计入输入预算。各模型的计数方法、余量是否需要及其大小，留待模型接入与上下文实现时确定。

上下文以材料清单组织，区分候选材料和实际纳入材料。清单应能表达材料来源与类别、token 开销、保留优先级、是否必须保留、允许的裁剪方式，以及组装位置。这里描述所需信息，不固定 Python 类型、数据库 schema 或配置文件格式。

候选材料包括共享规则与角色核心、当前输入、有效摘要、最近对话、本轮工具结果、场景提示词，以及角色表达示例等实际需要的内容。并非每次调用必须包含全部类别，也不固定每一类的额度或比例。

保留优先级用于决定空间不足时舍弃哪些材料；组装位置用于决定已选材料在请求中的顺序和消息结构。两者分别处理，不将“重要”直接解释为放到最后。

## 三、场景内容通过 prompt bundle 注入

场景背景作为专门的提示词内容统一管理在 `prompts/` 中，通过逻辑标识加载。它可以介绍有哪些场景及各自的背景，加载后的内容作为一项上下文材料交给 `src/context/`，参与同一套预算、选取与组装。

角色 bundle 继续负责角色身份与表达；场景 bundle 提供场景背景。两者可通过内容配置组合，runtime 不为具体角色或场景增加硬编码分支。场景 bundle 的确切标识、目录、变量和版本规则尚未确定，本文不新增实际提示词文件。

本任务不引入 SillyTavern 世界书的关键词扫描、递归触发、随机激活、向量检索或独立世界书引擎。也不预设由模型自主挑选场景或执行场景切换工具。是否每轮注入、采用哪份场景 bundle、插入位置以及超出预算时如何处理，需在实施前细化。

场景提示词描述可供交互参考的背景，不自动建立角色位置、虚拟生活或剧情推进状态，不代表场景里的事件已经发生。真实用户事实、共同经历和工具查询结果仍由历史、记忆及对应业务状态提供，不能混入共享场景内容以绕过归属和时间线检查。

## 四、模块协作与处理过程

1. `src/runtime/` 提供本次调用的用户、陪伴实例及执行归属，协调读取有效历史与记忆。
2. 提示词加载入口读取角色、共享规则和场景 bundle；模型接入入口提供所需的能力与预算配置。
3. `src/context/` 先排除不属于当前用户、陪伴实例或有效时间线的材料。保存在磁盘上不等于有资格进入上下文。
4. 确定本次预算，计算候选材料开销，按后续明确的保留与裁剪规则选取材料。场景内容也占用预算，不能在检查完成后再无上限追加。
5. 组织模型所需的消息与工具结构，在适配后的最终请求处校验预算和协议完整性，再交给模型调用入口。

具体数据结构和接口签名尚未确定。前端与 FastAPI 负责展示和通信，不维护第二套预算或上下文事实。

## 五、必须保留的行为边界

- 上下文裁剪不删除原始历史，也不直接改写已保存的摘要或角色内容。
- 被取消而未纳入有效历史的输出、回退后的失效消息及摘要，不能因相关性或剩余预算而重新进入请求。
- 裁剪历史与工具材料时保持合法的调用—结果关联及必要语义，不能只按字符数随意切断协议结构。
- 如果必需材料无法放入预算，应明确返回无法构建有效请求的状态；恢复或压缩策略需另行确定，不能静默丢弃关键输入或发送已知超限请求。
- 预算是上限，无需为填满空间而加入无关材料。
- 场景 bundle 不改变工具授权、执行范围或长期记忆写入规则。

## 六、实施前需细化的事项

1. 模型上下文上限、输出预留、计数方法、请求开销与必要余量的配置来源。
2. 各材料的保留优先级、必需性、裁剪单元、摘要覆盖与最近历史的衔接规则。
3. 历史或工具结果超限时的具体处理，以及是否请求既有 summary 工作流；本文不确定 summary 触发频率。
4. 场景 bundle 的逻辑标识、内容结构、变量、版本、选用方式、注入频率和消息位置。
5. 场景内容超限或缺失时的处理方式，必需材料超限后的用户可见状态。

上述事项未确定前，不把学习讨论中的 16,000 token 上限、2,000 token 输出预留或任何材料配额设为产品默认值。

Prompt Itemization 的完整请求快照、持久化审计和管理员检查界面不纳入本 issue；本次只记录预算材料选取与场景 bundle 注入，不据此宣称已有完整可观测性设计。

## 七、未来验收场景

- 为受控模型配置不同预算时，最终请求符合相应上限，输出预留与工具定义等开销得到正确计算。
- 候选材料超限时，依照明确规则选择或裁剪；原始历史与已保存的记忆保持不变。必需材料超限时明确失败，不发送已知无效请求。
- 同一 Run 得到工具结果后，下一次模型调用重新核算预算，并保留合法的调用—结果结构。
- 场景 bundle 能经统一加载入口成为上下文材料，内容计入总预算；修改场景资料不要求修改 runtime。
- 能配置所需场景背景而不依赖关键词扫描、递归检索或世界状态模拟。
- 用户隔离及管理员回退后，失效材料无法进入上下文，共享场景内容不夹带其他用户的历史或事实。

以上为待实现后的验收要求，不是已通过的测试结果。
